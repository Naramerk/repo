# Веб-консоль CoScientist-next

## Открыть сохранённые исследования

Из корня репозитория:

```bash
cd /Users/nargiza/CoScientist-next
uv run --extra api --extra mcp --with uvicorn --with websockets \
  python -m coscientist.api.serve \
  --data-root bench/lab/glm/live/fs3 \
  --catalog bench/lab/glm/checks_catalog.json \
  --host 127.0.0.1 --port 8480 \
  --stream-poll-interval-s 1 --run-wait-s 60
```

Открыть <http://127.0.0.1:8480/ui/>. Команда сама не запускает исследования и не
вызывает модели. Остановить сервер можно Ctrl+C. Для этого режима ключи моделей
и VPN не нужны. Каталог и исторические прогоны выше — локальные файлы этого Mac.

`--data-root` — папка, внутри которой непосредственно находятся папки исследований
с `events.db`. Например, `.../live/fs3` показывает `full-stack-3`; родительская
`.../live` не объединяет автоматически все вложенные каталоги прогонов.

## Где что находится

- **Ход работы:** задачи и события. Задачу можно открыть мышью или клавишами
  Tab и Enter/Space. «Исходная задача» раскрывает оригинальный запрос.
- **Результаты:** все попытки, включая отменённые без результата; вычисленный итог,
  заявление исполнителя, проверки и ссылки на исходные данные различаются.
- **Документы:** научный отчёт, ТЗ, НИР, ревью и артефакты. После завершения нажмите
  «Обновить документы», если отчёт ещё записывался. Файл без записи в журнале
  помечается отдельно. Исходный файл можно скачать.
- **Граф:** связи между вопросами, доказательствами и артефактами. Выберите фокус
  или узел. «Вписать» возвращает автоматический масштаб после ручного перемещения.
- **Решения человека:** план на согласовании и история решений. Ответить можно,
  пока активный владелец API-запуска ожидает решения. Старый журнал доступен для
  чтения; открытие страницы не возобновляет остановленный процесс.
- **Журнал:** исходные события для диагностики.

«Выполнено» — записанный итог выполнения процесса. Научную обоснованность нужно
оценивать по содержанию результата, проверкам и источникам. Статус этапа REPORT
в старом журнале может быть «Пропущено», хотя отчёты отдельно записаны после
завершения; такие документы видны во вкладке «Документы».

## Запустить новое исследование из браузера

Сервер должен быть запущен с `--run-presets /абсолютный/путь/presets.json`.
Форма содержит выбор подготовленного пресета и поле задачи. После запуска откройте
«Решения человека» и согласуйте план. Stop останавливает владельца и закрывает
фактически активный журнал, включая дочернее исследование после перепланирования.
Закрытие браузерной вкладки само по себе исследование не отменяет.

Полный формат пресета — в [console-presets.example.json](console-presets.example.json),
контракт — в [console.md](console.md). Пример требует замены путей к файлам;
он не загружается автоматически и не является готовой универсальной конфигурацией.
Для исследований нужны ключи выбранного провайдера в окружении сервера и доступ
к настроенным MCP. Heracleum требует VPN. До запуска проверьте модель и бюджеты
в карточке пресета. GLM допускается только 4.7 с часовым лимитом; недельный лимит
использовать нельзя. Альтернатива — настроенный DeepSeek.

После перезапуска сервера записанная история сохраняется, но прежний работающий
исполнитель не восстанавливается автоматически. Не считайте подключённый журнал
подтверждением активного вычисления.

## Что выбирается автоматически

- **План:** модель строит задачи и выбирает `tools_hint` внутри уже разрешённого
  набора инструментов.
- **Гипотезы и литература:** планировщик выставляет Need. Этап запускается, только
  если роль заранее подключена в `wired_roles` и настроена профилем. Иначе система
  отказывает. Полноценная связь гипотез → экспериментов → проверки ещё не завершена.
- **Отчёты:** запускаются после завершения, если заранее подключена роль `report`.
  Это настройка запуска, а не автоматический выбор роли по тексту задачи.
- **Критик и ревьюер:** тоже требуют предварительного подключения.

Профиль, модели, провайдер, MCP, бюджеты и доступные входные файлы задаёт оператор.
Аргументы MCP сейчас подаются через `tool_call_args`, кодер — через `coder_jobs`.
Автономной подготовки всех аргументов, программ и окружения пока нет. Поиск
литературы в профиле `litsearch` получает метаданные; загрузка и разбор полных
текстов этим профилем не обеспечиваются.

Этот интерфейс уже позволяет проверять реальные результаты и управлять
настроенными запусками. Полное функциональное и научное превосходство над старой
системой ещё не подтверждено.
